2. CURRENT ML SYSTEM
====================

The existing system uses a regression approach.

The model produces:

Repayment Score: 0–100

This is a model-estimated repayment score.

It is NOT a calibrated probability that the applicant will repay.

Never describe:

"Score 82 = 82% probability of repayment."

The correct interpretation is:

"A higher score represents a stronger model-assessed repayment profile."

The model currently uses these ten features:

1. Monthly Income
2. Age
3. Occupation
4. Existing Loan History
5. Debt-to-Income Ratio
6. Telecom Usage Score
7. Mobile Wallet Activity
8. Digital Purchase Frequency Pattern
9. Psychometric Score
10. Moderating Variable / Loan Size

The existing pipeline already performs preprocessing and uses XGBoost.

The existing system also has:

XGBoost
→ repayment score

SHAP
→ actual feature contributions

LLM
→ human-readable wording of the SHAP explanation

ReportLab
→ applicant PDF report

Keep these responsibilities separated.

The LLM must NEVER:

* calculate the repayment score
* modify the repayment score
* calculate SHAP values
* reverse feature contribution directions
* approve or reject a loan
* invent applicant information

7. FINANCIAL BEHAVIOR ASSESSMENT
================================

The current model expects a numeric psychometric_score.

A real applicant should NOT manually type a psychometric score.

Create a "Financial Behavior Assessment" that produces this feature.

Use approximately 12 carefully written questions across these dimensions:

A. Financial Discipline
B. Repayment Responsibility
C. Spending Control
D. Financial Planning

Use a 5-point Likert scale:

Strongly Disagree
Disagree
Neutral
Agree
Strongly Agree

Map answers internally from 1 to 5.

Include a balanced mixture of positively and negatively worded questions.

Reverse-score negative questions correctly.

Normalize the final questionnaire result to the exact psychometric score scale expected by the current trained model.

IMPORTANT:
Before implementing the normalization, inspect the training dataset and preprocessing code to determine the actual psychometric_score range used during model training.

Do not assume it is 0–100.

The inference value must match the training feature distribution.

Add response-consistency checks using logically related or reverse-worded question pairs.

A consistency warning must NOT automatically reject an applicant.

Treat it only as an assessment-quality indicator.

Clearly document that this questionnaire is a prototype financial-behavior assessment and is not a scientifically validated psychometric instrument.
